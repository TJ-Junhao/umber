# umber v0.1 — Design Spec

- Date: 2026-10-10
- Status: draft, awaiting owner review
- Scope: first release of umber, a Rust-powered plotting library for Python

## 1. Goal

umber is a plotting library for everyday 2D charts. It is written in Rust and used from Python.

It serves three use cases, all first-class:

1. **Everyday analysis**: good-looking charts with little code, straight from lists, numpy arrays and pandas/polars Series.
2. **Publication figures**: precise, reproducible SVG and PNG output with controlled typography.
3. **Large data**: millions of points render quickly because all per-point work happens in Rust.

Its defining trait is the API: no hidden state, one signature per function, strong static typing, and documentation visible on hover. Section 6 defines these rules.

### Success criteria for v0.1

- The four chart types in scope render correctly in all three built-in themes, as PNG and SVG.
- Every public API passes `pyright --strict` and `mypy --strict`. Wrong usage listed in Section 6.4 is reported as a static error.
- Every public type, enum member and function has a docstring with a runnable example, and CI runs all examples.
- The performance targets in Section 11 are met on the reference machine.

## 2. Scope

### In v0.1

- Chart types: `line`, `scatter`, `bar`, `grouped_bar`, `stacked_bar`, `hist`.
- One `Axes` per `Figure`.
- Scales: linear, log, category.
- Output: PNG (raster) and SVG (vector). By default, SVG text is converted to paths.
- Three built-in themes: `PIGMENT` (default), `GRAPHITE`, `MIDNIGHT`.
- Downsampling of large line series at render time.

### Not in v0.1 (candidates for v0.2 and later)

- Multiple axes per figure (subplots, shared axes, constrained layout)
- Jupyter inline display (`_repr_png_` / `_repr_svg_`)
- PDF output
- Interactive windows
- Statistical charts (box, violin, error bars, fill_between)
- Heatmap / imshow / contour, and a colormap system
- Time scale (`Scale.time() -> Scale[datetime]`): the generic design in Section 6.3 already leaves room for it
- User-supplied or system font selection
- Release automation to PyPI / crates.io

|---|---|

| Rust binding crate | `umber-py` (internal, not published) |

- Minimum Python version: **3.12**.
- The extension is built with PyO3 using `abi3-py312`, which gives one wheel per platform.
- The build backend is maturin.

## 4. Architecture

All drawing logic lives in Rust. The Python layer is a thin, fully typed façade that owns API ergonomics: signatures, docstrings, type-level guarantees and argument type checks.

### Render pipeline (inside `umber-core`)

```
Figure (built by the user)
  → resolve   data ranges, scales, ticks, legend entries, palette assignment
  → layout    measure text; place header, plot area, tick labels
  → Scene     backend-independent primitives: Path, Rect, Glyph run (as outlines), Marker batch
  → backend   PngBackend (tiny-skia) | SvgBackend
```

- **Building records, rendering computes.** Mark methods validate and store data immediately. Ranges, ticks and layout are computed only at render time, so the order of calls does not matter.
- **Single source of truth.** `Scene` is the only input to the backends. Text is shaped once and turned into glyph outlines. PNG and SVG therefore render the same geometry.
- **GIL release.** Rendering runs inside `py.allow_threads`.

### Text stack

- Shaping uses `rustybuzz`, outlines come from `ttf-parser`, and font lookup and system fallback use `fontdb`.
- Bundled fonts are embedded with `include_bytes!`, so the Rust crate and the Python wheel behave the same way.
- Characters missing from the bundled fonts (for example CJK) fall back to system fonts through `fontdb`.

## 5. Core data model (Rust)

- `Figure`: size in inches, a `Theme`, and `Option<Axes>`. The field is a single slot in v0.1 and is designed to become a collection later.
- `Axes`: x and y `ScaleKind`, title, subtitle, x/y labels, optional limits, and `Vec<Mark>`.
- `ScaleKind`: how values along one axis map to positions. In v0.1 the Rust API checks scale and data compatibility at runtime. Compile-time typing of axes is provided by the Python layer (Section 6.3).

  ```rust
  #[derive(Debug, Clone, Copy, PartialEq)]
  #[non_exhaustive]                 // room for `Time` later without a breaking change
  pub enum ScaleKind {
      Linear,
      Log { base: LogBase },
      Category,                     // order = first appearance across marks, resolved at render time
  }

  /// A logarithm base, guaranteed finite and > 1.
  #[derive(Debug, Clone, Copy, PartialEq)]
  pub struct LogBase(f64);          // private field: only constructible through `new`

  impl LogBase {
      pub const TEN: LogBase = LogBase(10.0);
      pub fn new(base: f64) -> Result<LogBase, Error>;   // Error::Style unless finite and > 1
      pub fn get(self) -> f64;
  }
  ```
- `Mark`: enum `Line | Scatter | Bar | GroupedBar | StackedBar | Hist`.
  - Each variant owns its data as `Arc<[f64]>` (categories as `Arc<[String]>`), its label, its color (`ColorSpec::{Auto, Palette(u8), Rgba(u32)}`) and its mark-specific options (`Dash`, `Marker`, `bins`).
  - Data is copied once from Python when the mark is added. The numpy buffer is read without an intermediate copy, but it is not kept, because a numpy array cannot be borrowed past the call.
- `Theme`: a plain immutable struct holding all visual tokens (Section 8). There is no global or mutable default.
- Errors: a `thiserror` enum `Error { Data(..), Style(..), Usage(..), Io(..) }`. Library code must not call `unwrap`, `expect` or `panic!` (`clippy::unwrap_used`, `clippy::expect_used`, `clippy::panic` set to `deny`).

The Rust public API mirrors the Python concepts (builder methods, typed enums). It is published as `0.x` and may change between minor versions.

## 6. Python API

### 6.1 Principles (binding)

1. **No hidden state.** There is no current figure or current axes, and no global rcParams. The user creates and holds every object. Quick functions return new objects and register nothing.
2. **One signature per function.** No overloads, no meaning that depends on the number of positional arguments, no format strings such as `"r--"`.
3. **No `**kwargs`.** Every parameter is listed explicitly with a precise type. Data parameters are positional. All other parameters are keyword-only (declared after `*`).
4. **No `Literal` in the public API.** A closed set of options is a standard-library `enum.Enum`. An open set (colors) is a value class with class-level constants. Either way, a user reading `dash: Dash` on hover can type `Dash.` and get completions.
5. **Errors are raised at the call site.** Mark methods validate immediately instead of waiting until save time (Section 9).
6. **Setters only set.** `ax.title("...")` sets a value and returns `Self`. No method changes its meaning depending on whether arguments are passed.
7. **Every parameter type is a named, importable type.** Hover must show `Color`, `Dash`, `Values[float]`, never an expanded union. Type aliases use PEP 695 `type` statements.
8. **Use generics where they carry meaning.** The axis value types flow through `Axes[X, Y]` (Section 6.3).
9. **Everything public is documented with a runnable example** (Section 10).

### 6.2 Value types and enums

```python
class SupportsArray(Protocol):
    def __array__(self) -> Any: ...

type Values[T] = Sequence[T] | SupportsArray
```

`Values[T]` accepts Python sequences, numpy arrays and pandas/polars Series. For non-sequence inputs the dtype is checked at runtime, and a mismatch raises `DataError`.

```python
class Dash(Enum):            SOLID, DASHED, DOTTED
class Marker(Enum):          CIRCLE, SQUARE, TRIANGLE, DIAMOND, CROSS
class Font(Enum):            SOURCE_SERIF_4, IBM_PLEX_SANS, GEIST, INTER, JETBRAINS_MONO
class TickLabelPlacement(Enum): ABOVE_GRIDLINE, OUTSIDE
class LegendStyle(Enum):     HEADER, DIRECT, CHIPS
class AreaFill(Enum):        NONE, GRADIENT
class GridLines(Enum):       HORIZONTAL, VERTICAL, BOTH, NONE
class SvgText(Enum):         OUTLINES, EDITABLE
```

- All enums are defined in pure Python as real `enum.Enum` subclasses. PyO3 `#[pyclass]` enums are not `enum.Enum` at runtime and break iteration, exhaustiveness checks and `stubtest`.
- Each member's `.value` is an `int`. The binding layer maps that int to the Rust enum.

**`Color`** is an immutable value class:

```python
class Color:
    AUTO: ClassVar[Color]      # next color of the theme palette, in series order within the axes
    BLACK, WHITE, GRAY, RED, ORANGE, YELLOW, GREEN, TEAL, BLUE, PURPLE, PINK, BROWN: ClassVar[Color]
    @staticmethod
    def hex(code: str) -> Color: ...            # "#RRGGBB" or "#RRGGBBAA"; anything else raises StyleError
    @staticmethod
    def rgb(r: int, g: int, b: int) -> Color: ...   # 0..255 each, else StyleError
    @staticmethod
    def palette(index: int) -> Color: ...       # index-th color of the figure's theme palette (wraps around)
    def alpha(self, a: float) -> Color: ...     # returns a new Color; 0.0..1.0, else StyleError
```

Named constants have fixed values. They do not depend on the theme.

| Name | Hex | Name | Hex |
|---|---|---|---|
| BLACK | `#1A1A1A` | GREEN | `#4E9A5E` |
| WHITE | `#FFFFFF` | TEAL | `#2E8B8B` |
| GRAY | `#8C8C8C` | BLUE | `#3366B8` |
| RED | `#D64933` | PURPLE | `#7D5BA6` |
| ORANGE | `#E8853D` | PINK | `#D46A92` |
| YELLOW | `#E9B949` | BROWN | `#7A5236` |

A parameter typed `Color` accepts only `Color`. Passing a `str` raises `TypeError` at the call site.

### 6.3 Generic axes

```python
class Scale[T]:
    @staticmethod
    def linear() -> Scale[float]: ...
    @staticmethod
    def log(base: float = 10.0) -> Scale[float]: ...     # base > 1, else StyleError
    @staticmethod
    def category() -> Scale[str]: ...                    # categories ordered by first appearance

class Figure:
    def __init__(self, width: float = 6.0, height: float = 4.0, *,
                 theme: Theme = Theme.PIGMENT) -> None: ...          # inches; > 0 else StyleError
    def add_axes(self, *, x: Scale[X] = Scale.linear(),
                 y: Scale[Y] = Scale.linear()) -> Axes[X, Y]: ...    # X, Y default to float
    def save_png(self, path: str | os.PathLike[str], *, dpi: int = 200) -> None: ...
    def save_svg(self, path: str | os.PathLike[str], *, text: SvgText = SvgText.OUTLINES) -> None: ...
    def to_png(self, *, dpi: int = 200) -> bytes: ...
    def to_svg(self, *, text: SvgText = SvgText.OUTLINES) -> str: ...
```

- `X` and `Y` are `typing_extensions.TypeVar(..., default=float)`. This is required because without TypeVar defaults, mypy infers `Axes[Any, Any]` for `add_axes()` and asks users to annotate their own variables (verified, Section 13).
- The default argument needs one `# type: ignore[assignment]` inside umber's own source. Users never see it.
- Calling `add_axes()` a second time on the same figure raises `UsageError` in v0.1.
- Saving a figure without axes renders the background only.

```python
class Axes[X, Y]:
    @property
    def figure(self) -> Figure: ...

    # marks
    def line(self, x: Values[X], y: Values[Y], *, label: str = "",
             color: Color = Color.AUTO, dash: Dash = Dash.SOLID) -> Self: ...
    def scatter(self, x: Values[X], y: Values[Y], *, label: str = "",
                color: Color = Color.AUTO, marker: Marker = Marker.CIRCLE) -> Self: ...
    def bar(self: Axes[str, float], categories: Values[str], heights: Values[float], *,
            label: str = "", color: Color = Color.AUTO) -> Axes[str, float]: ...
    def grouped_bar(self: Axes[str, float], categories: Values[str],
                    series: Sequence[BarSeries]) -> Axes[str, float]: ...
    def stacked_bar(self: Axes[str, float], categories: Values[str],
                    series: Sequence[BarSeries]) -> Axes[str, float]: ...
    def hist(self: Axes[float, float], values: Values[float], *, bins: int = 30,
             label: str = "", color: Color = Color.AUTO) -> Axes[float, float]: ...

    # text
    def title(self, text: str) -> Self: ...
    def subtitle(self, text: str) -> Self: ...
    def xlabel(self, text: str) -> Self: ...
    def ylabel(self, text: str) -> Self: ...

    # limits (continuous axes only)
    def xlim(self: Axes[float, Y], low: float, high: float) -> Axes[float, Y]: ...
    def ylim(self: Axes[X, float], low: float, high: float) -> Axes[X, float]: ...

class BarSeries:
    def __init__(self, label: str, heights: Values[float], *, color: Color = Color.AUTO) -> None: ...
```

- The legend is shown exactly when at least one mark has a non-empty `label`. Its form comes from the theme's `LegendStyle`.
- A bar or stacked bar with a negative height draws below the baseline. `stacked_bar` stacks positive and negative values separately.
- `xlim` / `ylim` with `low >= high`, or with non-positive values on a log axis, raise `StyleError`.

### 6.4 Static guarantees (verified for pyright and mypy, Section 13)

```python
ax = ub.Figure().add_axes()                           # Axes[float, float]
ax.line(t, y).xlim(0, 10)                             # ok, chaining keeps Axes[float, float]
ax.bar(["A", "B"], [3, 5])                            # error: bar needs x = Scale[str]

cats = ub.Figure().add_axes(x=ub.Scale.category())    # Axes[str, float]
cats.bar(["A", "B"], [3, 5])                          # ok
cats.line([0.1, 0.2], [1, 2])                         # error: x must be Values[str]
cats.hist([1.0])                                      # error: hist needs Axes[float, float]
cats.xlim(0, 1)                                       # error: xlim needs a continuous x axis
```

### 6.5 Quick functions

Each quick function creates a new `Figure(theme=theme)` with one axes, adds one mark and returns the axes. It has the same parameters as the matching mark method, plus `theme`.

```python
def bar(categories: Values[str], heights: Values[float], *, ...) -> Axes[str, float]: ...

```

### 6.7 API evolution rules

- A new parameter is always keyword-only and has a default, so existing calls keep working and the new parameter shows up in signature help and completion.
- If a mark method would exceed 6 style parameters, related parameters are grouped into a typed style object (for example `stroke: Stroke`) instead of being added flat.
- Removing or renaming a public name requires one minor release with a `DeprecationWarning` first.

## 7. Rendering rules

- **Units.** Figure size is in inches. All lengths inside a theme (line widths, marker sizes, radii, gaps, font sizes) are in points (1/72 inch). PNG pixel size is `inches × dpi`.
- **Layout.** The outer padding is 12 pt. Top to bottom, the layout is:
  - a header block: title, then subtitle, then the legend row, each omitted and collapsed when empty;
  - the plot area;
  - the x tick labels and the x label.

  The y tick labels and the y label sit to the left of the plot area, or above the gridlines for `ABOVE_GRIDLINE`.
- **Ticks.** Continuous axes use the Extended Wilkinson algorithm (Talbot, Lin & Hanrahan 2010), targeting about 5 ticks on x and about 4 on y. Log axes put ticks at powers of the base. Category axes put one tick per category, centered in its band. There are no minor ticks in v0.1.
- **Auto limits.**
  - A continuous axis expands to the enclosing ticks ("nice limits").
  - Exception: the x axis of an axes whose marks are all lines uses the exact data extent.
  - The y axis of `bar`, `grouped_bar`, `stacked_bar` and `hist` always includes 0.
  - Empty data falls back to 0–1.
- **Baseline.** If 0 is inside the y range, a baseline is drawn at y = 0 in the theme's baseline color and width. Otherwise it is drawn at the bottom of the plot area. When the tick label placement is `ABOVE_GRIDLINE`, the gridline label that coincides with the baseline is omitted.
- **Missing values.** NaN in a line breaks the line at that point. NaN in a scatter skips the point. ±inf anywhere raises `DataError` when the mark is added.
- **Line downsampling.** When a line has more than 4 × the plot-area width in device pixels, M4 downsampling keeps the first, last, minimum and maximum point per pixel column. The result is visually lossless. For SVG, the device width is computed at a nominal 300 dpi.
- **Scatter.** Each marker is filled at the theme's marker alpha and has a 0.8 pt outline in the background color, which separates overlapping points. All points of a series are drawn as one batch from a single marker path.
- **Bars.** In `grouped_bar`, the bar group occupies 72 % of the category band. Bars within a group have a 2 pt gap. Corner radius comes from the theme and applies only to the end away from the baseline.
- **Histogram.** Bins are equal-width over the data's min to max range. The gap between bars comes from the theme. With `AreaFill.GRADIENT`, bars get a vertical gradient from 0.95 alpha at the top to 0 at the baseline, plus a 1.6 pt top edge in the solid color.
- **Line area fill.** With `AreaFill.GRADIENT`, the area between each line and the baseline is filled with a vertical gradient from 0.32 alpha at the line to 0 at the baseline.
- **Legend styles.**
  - `HEADER` shows a row of swatches with labels under the subtitle. The swatch is a short line for line marks, a dot for scatter, and a square for bars and histograms.
  - `DIRECT` labels each line at its last finite point, in the line's color, at semibold weight. Labels that would overlap are nudged vertically so they are at least 1.2 × the font size apart. Non-line marks fall back to the `HEADER` row.
  - `CHIPS` shows a row of rounded pills under the subtitle. Each pill is tinted with the series color at 0.14 alpha and holds a dot and the label.
- **SVG text.** The default `SvgText.OUTLINES` writes text as paths, which matches the PNG output exactly and needs no fonts on the viewer's machine. `SvgText.EDITABLE` writes `<text>` elements with a `font-family` stack, so the text can be edited later.
- **PNG background.** The PNG is opaque and uses the theme background color.

## 8. Themes

### 8.1 Type

`Theme` is immutable. Built-in themes are class constants: `Theme.PIGMENT` (the default), `Theme.GRAPHITE` and `Theme.MIDNIGHT`.

To customize a theme, call chainable `with_*` methods. Each takes exactly one typed argument and returns a new `Theme`:

```python
theme = Theme.PIGMENT.with_line_width(2.5).with_font_scale(1.2)
fig = ub.Figure(6, 4, theme=theme)
```

`dataclasses.replace` is deliberately not used, because pyright does not check its field names or types (verified, Section 13).

`with_*` methods:

- `with_palette(colors: Sequence[Color])`: 1 to 16 concrete colors. `AUTO` and `palette()` references raise `StyleError`.
- Colors: `with_background`, `with_text_color`, `with_muted_color`, `with_grid_color`, `with_baseline_color`, all taking `Color`.
- `with_grid_lines(GridLines)`, `with_grid_dash(Dash)`
- `with_title_font(Font)`, `with_body_font(Font)`, `with_font_scale(float)`
- `with_line_width(float)`, `with_marker_size(float)`, `with_marker_alpha(float)`, `with_baseline_width(float)`
- `with_bar_corner_radius(float)`, `with_hist_gap(float)`
- `with_tick_label_placement(TickLabelPlacement)`, `with_legend_style(LegendStyle)`, `with_area_fill(AreaFill)`

Numeric values must be finite. Sizes must be ≥ 0 (> 0 for `font_scale`, line width and marker size). Alphas must be within 0..1. Anything else raises `StyleError`.

### 8.3 Fonts

Five OFL-licensed families are bundled: Source Serif 4, IBM Plex Sans, Geist, Inter and JetBrains Mono.

- Each family ships two weights, regular and semibold, subset to Latin, Latin-1 Supplement, Latin Extended-A and common punctuation and symbols.
- Each family's license file ships with the crate and the wheel.
- Budget: the fonts should add 3 MB or less to the wheel. This is an estimate and is measured in the implementation plan.

## 9. Errors

| Exception | Base classes | Raised for |
|---|---|---|
| `UmberError` | `Exception` | Base of all umber errors |
| `DataError` | `UmberError`, `ValueError` | Length mismatch, not 1-D, ±inf, wrong dtype, non-positive values on a log axis |
| `StyleError` | `UmberError`, `ValueError` | Invalid non-data argument values: color format, alpha range, sizes, `bins < 1`, log base, limits, palette |
| `UsageError` | `UmberError` | Calling the API in an unsupported way, e.g. a second `add_axes()` in v0.1 |
| `TypeError` (builtin) | — | Wrong argument type, e.g. `color="red"` |
| `OSError` (builtin) | — | File write failures, not wrapped |

- **Message format**: `<Class>.<method>(): <what is wrong>; <what is required>.`
  Example: `DataError: Axes.line(): x has 120 values but y has 118; x and y must have the same length.`
- **Where errors are raised**:
  - Type checks on enums, `Color`, `Theme` and `BarSeries` happen in the Python layer and raise `TypeError`.
  - Data conversion and validation happen in Rust and map to `DataError` / `StyleError` / `UsageError`.
- **Panics**: a Rust panic surfaces as PyO3's `PanicException` and always counts as a bug.

## 10. Documentation rules

- **Language.** All project documentation is English: docstrings, README, specs, code comments. Chinese appears only in separate files with a `-ZH` suffix, for example `README-ZH.md`.
- **Format.** Docstrings use Google style. A type's docstring states what it is, where it is used and when to use it. A function's docstring states its purpose, each argument (including what the default means), the return value, the raised exceptions, and an `Example:` section.
- **Enum members** each have an attribute docstring, written as a string literal right after the assignment. Pyright shows it on hover.
- **Examples** are self-contained: they include imports and data, so they can be copied and run as-is. CI runs them with `pytest --doctest-modules` in a temporary directory.
- **Enforcement**:
  - `ruff` `D` rules with the Google convention.
  - A test that walks `umber.__all__` and fails on any public class, method or function missing a summary or an `Example:` section.
  - An AST-based test that fails on any enum member without a docstring.
- **Rust.** `umber-core` sets `#![deny(missing_docs)]`. Every `pub` item has an `# Examples` section, which `cargo test --doc` runs.

## 11. Testing and CI

1. **Rust unit tests**: ticks, scales, M4 downsampling, layout, color conversion, legend nudging. Ticks and downsampling also get `proptest` property tests:
   - ticks cover the data range and use steps from the allowed set;
   - downsampling preserves the per-column minimum and maximum.
2. **Scene snapshots**: `insta` text snapshots of `Scene` for a fixed set of figures.
3. **PNG golden images**:
   - The gallery covers every chart type × every theme, plus log scale, NaN gaps, negative bars and the empty figure.
   - Images are compared with a per-pixel tolerance. A failure writes a `*.diff.png`.
   - Golden images are updated only with `UPDATE_GOLDEN=1`.
4. **Python tests**: API behaviour, every error path and its message, docs completeness (Section 10) and doctests.
5. **Type tests**:
   - Files in `tests/typing/` are checked by both `pyright --strict` and `mypy --strict`.
   - Expected errors are asserted with ignore comments, together with `reportUnnecessaryTypeIgnoreComment` (pyright) and `warn_unused_ignores` (mypy). A wrong usage that stops being flagged therefore fails CI.
   - `stubtest` validates `_umber.pyi` against the extension.
6. **Benchmarks** (`criterion`; the reference machine is the owner's Apple Silicon Mac):
   - a 1,000,000-point line to PNG at 6×4 in, 200 dpi, in < 100 ms;
   - a 100,000-point scatter to PNG under the same settings in < 200 ms.

   These are targets and have not been measured yet. The implementation plan calibrates them against a prototype. CI tracks benchmark regressions but does not gate on absolute times.
7. **CI matrix**: Linux, macOS and Windows × Python 3.12, 3.13 and 3.14. Every build runs `cargo clippy -D warnings` and `cargo fmt --check`, plus `ruff check` and `ruff format --check`.

## 12. Repository conventions

- The repository is hosted at `github.com/TJ-Junhao/umber` and is **private** for now. External contributions are not accepted at this stage.
- `main` is protected. Every change lands through a pull request: direct pushes, force pushes and branch deletion are blocked, and the rules also apply to admins. History is linear (squash or rebase merges only), and review conversations must be resolved before merging.
- All changes go through CI. Once the CI workflow from Section 11 exists, its jobs are added to `main`'s required status checks, and a pull request can merge only when they pass and the branch is up to date with `main`.

- Commit messages and PR descriptions carry **no trailers**: no `Co-Authored-By:` and no generated-by attribution lines.
- All documentation is in English, with Chinese only in `-ZH` files (Section 10).
- Agent tooling files are never committed: `.claude/`, `.codex/`, `.agent/`, `CLAUDE.md`, `AGENT.md` and `AGENTS.md` are git-ignored. Agent instructions such as a local `CLAUDE.md` stay on the developer's machine.

## 13. Verified facts (spike, 2026-10-10)

The checks below were run with the latest `pyright` and `mypy --strict` on a stub prototype.

- `Axes[X, Y]` with self-typed methods (`self: Axes[str, float]`) correctly accepts the valid calls in Section 6.4 and rejects every invalid one, in both checkers, with no false positives in user code.
- Without TypeVar defaults, mypy infers `Axes[Any, Any]` for `add_axes()` and demands annotations in user code. TypeVar defaults are therefore required.
- The PEP 696 syntax `def f[X = float]` is a `SyntaxError` on Python 3.12. `typing_extensions.TypeVar("X", default=float)` works on 3.12 at runtime and in both checkers. mypy needs one `# type: ignore[assignment]` on the default argument inside umber's source.
- `dataclasses.replace` is validated by mypy but **not** by pyright. Hence the `with_*` methods in Section 8.1.
